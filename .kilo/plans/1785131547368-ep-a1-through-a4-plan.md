## 5. EP-A3 — Device Management (Build Everything)

**Priority:** 🔴 Must — blocks nothing but is core CMS functionality.

### A3.1 — Device API Routes

#### 5.1.1 `GET /api/admin/devices`
- Auth: `requireAdminAuth()` (any role)
- Query params: `status` (draft/published), `brand` (slug), `category`, `page`, `limit`
- Joins: `brand:brands(*)` for brand name/logo
- Sort: `updated_at` descending
- Returns: `{ data, total, page, limit }`

#### 5.1.2 `POST /api/admin/devices`
- Auth: `requireAdminAuth()`, block `viewer`
- Body validation:
  - `name` required, min 2 chars
  - `slug` required, unique check
  - `brand_id` required (must exist in `brands`)
- Server-side computation:
  - `score_overall` = weighted formula from 5 sub-scores + `site_settings` weights
  - `slug` uniqueness check → 409 if duplicate
- Insert into `devices` table
- Trigger search reindex if `status === 'published'`
- Returns `{ data }` with 201

#### 5.1.3 `GET /api/admin/devices/[id]`
- Auth: `requireAdminAuth()`
- Returns single device with `brand:brands(*)` join
- 404 if not found

#### 5.1.4 `PATCH /api/admin/devices/[id]`
- Auth: `requireAdminAuth()`, block `viewer`
- Same validation as POST
- Recompute `score_overall` on save
- Slug uniqueness check (excluding current ID)
- Trigger search reindex if status changes to published
- Returns `{ data }`

#### 5.1.5 `DELETE /api/admin/devices/[id]`
- Auth: `requireAdminAuth()`, admin only
- Soft-delete recommended: set `status = 'draft'` instead of hard delete (preserves relationships)
- **Or** hard delete per spec (spec says "Delete device" without soft-delete). **Decision:** Hard delete per spec, but warn about orphaned related content in plan notes.
- Returns `{ success: true }`

## 8. API Route Pattern to Follow

All admin API routes follow this pattern (from existing articles/brands routes):

```ts
import { NextRequest, NextResponse } from 'next/server'
import { requireAdminAuth, getAdminClient } from '@/lib/admin/require-admin'

export async function GET(request: NextRequest) {
  try {
    await requireAdminAuth()
    const supabase = await getAdminClient()
    // ... query ...
  } catch (e) {
    const message = e instanceof Error ? e.message : 'Unauthorized'
    return NextResponse.json({ error: message }, { status: 401 })
  }
}

export async function POST(request: NextRequest) {
  try {
    const adminUser = await requireAdminAuth()
    if (adminUser.role === 'viewer') {
      return NextResponse.json({ error: 'Forbidden' }, { status: 403 })
    }
    // ... validate, insert ...
  } catch (e) {
    const message = e instanceof Error ? e.message : 'Unauthorized'
    return NextResponse.json({ error: message }, { status: message === 'Forbidden' ? 403 : 401 })
  }
}
```

## 10. Risks & Decisions

### R1: Google OAuth Not Enabled
**Risk:** Users see "Unsupported provider: provider is not enabled" when clicking Google sign-in.  
**Decision:** This is a Supabase dashboard config issue, not code. Must enable Google provider in Supabase Auth settings + add OAuth client credentials.

### R2: `site_settings` Table May Not Exist
**Risk:** Device score_overall computation needs weights from `site_settings`. If table is empty, default weights from spec (0.20, 0.25, 0.25, 0.15, 0.15) must be used.  
**Decision:** Add fallback defaults in API route. Seed `site_settings` if table is empty.

### R3: Brand Slug Uniqueness
**Risk:** Current brands API checks slug uniqueness on create but not on edit.  
**Decision:** Fix brands PATCH to exclude current ID from uniqueness check (same pattern as articles).

### R4: Device Score Computation
**Risk:** Spec says `(d×0.20 + p×0.25 + c×0.25 + b×0.15 + v×0.15) × 10`. These weights must come from `site_settings`.  
**Decision:** Create helper `computeOverallScore(scores, weights)` used by device API routes. Default weights match spec if `site_settings` is empty.

### R5: Soft vs Hard Delete
**Risk:** Spec says "Delete device" but devices have foreign keys (`related_video_id`, `buy_links` is JSONB).  
**Decision:** Hard delete per spec. Ensure `ON DELETE SET NULL` is set on foreign keys, or use `CASCADE` where appropriate. Check existing migration 001/002/003 for FK constraints.

### R6: Tiptap Version
**Risk:** Spec calls for `@tiptap/starter-kit` etc. Current package is `@tiptap/react: ^3.29.0`.  
**Decision:** v3 uses different extension import paths. Current `TiptapEditor.tsx` works — keep existing imports and toolbar.
